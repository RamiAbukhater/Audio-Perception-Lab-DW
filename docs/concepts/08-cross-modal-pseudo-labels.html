Object detection, sync, and cross-modal pseudo-labels

The project's central trick is to let a camera do the labelling. When the audio cluster for "beep-beep-beep" keeps showing up while a frozen object detector reports a microwave in view, we can guess that cluster means "microwave" and train an audio classifier on that guess. This page covers the detector, getting audio and video onto the same clock, deciding when a guess is trustworthy, and the iterative loop that improves the student model generation by generation.

The big idea

Labelling sounds by hand is slow. Labelling images is a solved problem for many everyday objects: detectors trained on COCO find microwaves, keyboards, laptops, and sinks reliably. Sound and sight are correlated in time: a microwave beeps when someone is standing at it, typing happens when a person sits at a keyboard. The project turns that correlation into labels:

  1. Record synchronised audio and video in an indoor space.
  2. Run a frozen detector on video frames → "what is visible, and where" over time.
  3. Embed and cluster the audio → "which windows sound alike" (Concept 7).
  4. Find clusters that reliably co-occur with a visual class → assign a pseudo-label, but only when confidence is high.
  5. Train a student audio classifier on the pseudo-labels, re-embed, re-cluster, repeat.

What an object detector outputs

A detector like YOLOv8 takes an image and returns a list of detections. Each has a bounding box (pixel coordinates), a class from its training vocabulary, and a confidence in [0, 1]. Internally it predicts many candidate boxes and removes duplicates with non-maximum suppression (NMS): keep the most confident box, drop any other box of the same class that overlaps it by more than an IoU threshold.

from ultralytics import YOLO

detector = YOLO("yolov8n.pt")                      # nano model, COCO's 80 classes, frozen
results = detector(frame, conf=0.25, verbose=False)[0]
for box in results.boxes:
    cls_name = results.names[int(box.cls)]          # e.g. "microwave", "keyboard", "person"
    conf = float(box.conf)
    x1, y1, x2, y2 = box.xyxy[0].tolist()

For the project's open vocabulary and per-object identity, Ultralytics' YOLO-World takes a text list of class names, and track keeps an id per object across frames:

from ultralytics import YOLOWorld

detector = YOLOWorld("yolov8s-world.pt")           # open-vocabulary, frozen
detector.set_classes(["microwave", "kettle", "coffee grinder", "door", "printer"])
results = detector.track(frame, persist=True, verbose=False)[0]   # persist ids across calls
for box in results.boxes:
    name = results.names[int(box.cls)]
    track_id = int(box.id) if box.id is not None else None        # "microwave #1" vs "#2"
Check the vocabulary before you design the study

COCO's 80 classes include microwave, oven, toaster, sink, refrigerator, keyboard, mouse, laptop, cell phone, tv, clock, hair drier, and person. They do not include doorbell, kettle, blender, door, or faucet. For classes outside the vocabulary you need an open-vocabulary detector (for example YOLO-World or OWL-ViT, prompted with text like "doorbell"), a fine-tuned detector, or a different visual cue (a door opening, a person at the door). Decide this early; it shapes the class list.

The project uses an open-vocabulary detector by default, because its targets are exactly the sounds a fixed audio ontology misses. Tracking adds identity, so two microwaves become microwave #1 and microwave #2, which the spatial gate can tell apart.

Two other facts to keep in mind. First, visible is not sounding: a keyboard is in view all day but makes noise only when someone types. Useful visual cues are often about activity (a person's hands near the keyboard, the microwave door opening, a box that appears or moves) rather than mere presence. Second, the detector has its own errors; a confidence threshold of 0.5 or higher, plus requiring a detection to persist over several frames, removes most flicker.

Getting audio and video on one clock

Pseudo-labels are only as good as the alignment. If video runs 400 ms behind audio, a door slam gets paired with the frame before the door moved. The /core/sync engine must put both streams on one timeline:

  • Use one clock. Stamp audio buffers and video frames with the same monotonic clock on the same machine at capture time (time.monotonic_ns()), not with file creation times or two devices' wall clocks.
  • Audio time is sample-accurate. Sample \(n\) of a buffer that started at \(t_0\) happened at \(t_0 + n/f_s\). Video timestamps jitter (frames are dropped, exposure varies); trust the per-frame timestamp, not "frame index ÷ 30".
  • Measure the offset once. Clap in front of the camera. The clap's onset in audio and the frame where the hands meet should agree; their difference is the capture latency to subtract. Re-check after any hardware change.
  • Window both streams the same way. For each audio window \([t, t + 1\,\text{s})\), aggregate detections from frames whose timestamps fall in that window: for example the maximum confidence per class, or the fraction of frames in which the class appears.
import numpy as np

def visual_tags_per_window(win_starts, win_len, frame_times, frame_dets, classes, min_conf=0.5):
    """For each audio window, the max detector confidence of each class over the frames inside it.

    win_starts: (W,) window start times in seconds, on the shared clock
    frame_times: (F,) frame timestamps on the same clock
    frame_dets: list of F lists of (class_name, conf)
    returns: (W, C) array of confidences in [0, 1]
    """
    idx = {c: k for k, c in enumerate(classes)}
    tags = np.zeros((len(win_starts), len(classes)), dtype=np.float32)
    for w, t0 in enumerate(win_starts):
        lo, hi = np.searchsorted(frame_times, [t0, t0 + win_len])
        for dets in frame_dets[lo:hi]:
            for name, conf in dets:
                if name in idx and conf >= min_conf:
                    tags[w, idx[name]] = max(tags[w, idx[name]], conf)
    return tags

Co-occurrence: linking clusters to objects

With a cluster id per audio window and a tag vector per window, count how often each cluster appears together with each visual class. Raw counts are misleading, because a class that is visible all day (the keyboard) co-occurs with everything. Normalise by how often each appears on its own. Lift (a form of pointwise mutual information) does that:

\[ \text{lift}(c, y) = \frac{P(\text{cluster}=c,\ \text{tag}=y)}{P(\text{cluster}=c)\,P(\text{tag}=y)}. \]

Lift is 1 when cluster and tag are independent and large when they appear together far more than chance. A cluster \(c\) is a candidate for label \(y\) if its lift with \(y\) is high and clearly higher than with any other class, and the pair has been seen enough times to trust (say at least 20 windows).

def cluster_tag_lift(cluster_id, tags, n_clusters, thresh=0.5, eps=1e-9):
    present = (tags >= thresh).astype(np.float32)                   # (W, C) binary
    onehot = np.eye(n_clusters, dtype=np.float32)[cluster_id]       # (W, K)
    joint = onehot.T @ present / len(cluster_id)                    # (K, C)  P(c, y)
    p_c = onehot.mean(0)[:, None]                                   # (K, 1)  P(c)
    p_y = present.mean(0)[None, :]                                  # (1, C)  P(y)
    counts = onehot.T @ present                                     # (K, C)  support
    return joint / (p_c * p_y + eps), counts

Confidence gating

The spec's "confidence-scoring policy" is the heart of the project: a pseudo-label is assigned only when several independent signals agree. A sensible first policy, applied per audio window:

  1. Visual confidence: the matching class is detected in this window with confidence ≥ \(\tau_v\) (for example 0.6), and persists across frames.
  2. Cluster–class association: the window's cluster has lift ≥ \(\tau_\ell\) with that class, based on enough support.
  3. Audio confidence: the window is close to its cluster centroid (distance below a percentile threshold), or, from generation 2 on, the student classifier itself agrees with probability ≥ \(\tau_a\).
  4. Temporal agreement (optional, stronger): the audio onset falls within a short tolerance of a visual change (door opening, person arriving).
  5. Spatial agreement (the project's addition): the sound must arrive from where the detected object is. A microphone array gives the sound's direction, the depth camera gives the object's 3-D position, and a room map says whether the path between them is clear. The label is kept if the direct path points at the object, or if the strongest arrival is an echo that the room geometry traces back to it. It is rejected if the sound comes from a different object, from a wall, or from off camera. This is the spatial gate, built up over Concepts 9 to 11.

The spatial check matters most exactly where co-occurrence fails: when several labelled objects are visible at once (it picks the one the sound came from), when the true source is out of view (it refuses a label that co-occurrence alone would have given), and when echoes make a sound seem to come from a visible but silent object.

Windows that fail any check get no label, not a "background" label. The output is a small, high-precision labelled set. Measure that precision on your hand-labelled check set every generation, and report the trade-off curve of pseudo-label precision versus how many windows got labelled as you vary the thresholds.

The teacher-student loop

This is self-training, in the family of noisy student training (Xie et al., 2020) and pseudo-labelling (Lee, 2013):

  1. Generation 0: an encoder trained self-supervised on the room's own audio produces embeddings (pretrained audio models are kept out of the loop and used as baselines); clustering plus gating gives the first pseudo-labels.
  2. Train the student (encoder + classification head) on those labels, with strong augmentation (noise, SpecAugment, mixup). Augmentation is what lets the student generalise beyond its teacher instead of copying its mistakes.
  3. Relabel: run the student over all unlabelled windows. Its confident predictions, still gated by visual evidence, become the next generation's labels. Re-embed and re-cluster with the new encoder.
  4. Repeat and track, per generation: accuracy and macro-F1 on the hand-labelled test set, pseudo-label precision and coverage, and cluster quality. Those curves are the "classification convergence over generation cycles" the spec asks for.

A useful extra result: once trained, does the audio classifier recognise sounds when the object is out of view? That is the whole point of learning from sound, and the spatial gate is what makes those out-of-view examples identifiable.

Confirmation bias and other traps

  • Confirmation bias: a wrong pseudo-label trains the student to be confidently wrong, which produces more of the same wrong label next generation. Keep thresholds high, keep the visual gate on every generation, cap how many labels any class can gain per generation, and watch precision on the check set. If precision falls, stop.
  • Class imbalance: frequent sounds (typing) swamp rare ones (doorbell). Balance the pseudo-labelled set per class, or weight the loss.
  • Spurious correlation: if the coffee machine is always used right after the microwave, the "microwave" label may attach to coffee-machine sounds. Data from several days and rooms, and the lift test, reduce this; looking at (and listening to) each cluster removes most of it.
  • Leakage through time: split train and test by day or session (Concept 6).
  • Privacy: an always-on camera and microphone in a shared space records people. Get consent from everyone who uses the space, post a notice, keep raw recordings off public repositories, and delete video once detections are extracted if you do not need it. Check with the faculty advisor whether IRB review applies.

Check your understanding

Q1.The keyboard is detected in 90% of all windows. Cluster 12 co-occurs with "keyboard" in 92% of its windows. Is cluster 12 typing?

Not on this evidence. Lift is 0.92 / 0.90 ≈ 1.02, essentially independent. Almost every cluster co-occurs with the keyboard because it is always visible. You need an activity cue (hands on keys) or a cluster whose lift is clearly above 1.

Q2.Video timestamps lag the audio by 300 ms and windows are 1 s long. What goes wrong, and how do you detect it?

Short events near window edges get paired with the wrong window's detections, weakening co-occurrence and creating wrong labels. Detect it with a clap test or by cross-correlating audio onsets with visual change events; subtract the measured offset.

Q3.Why give failing windows no label rather than a "background" label?

Failing the gate means "not sure", not "nothing happened". Labelling them background would teach the student that real but unconfirmed events (an off-screen microwave) are background, which is exactly the generalisation we want it to make the other way.

Q4.What role does strong augmentation play in the student's training?

It forces the student to match the pseudo-labels under harder conditions than the teacher saw, so it learns more robust features and can end up better than the teacher, rather than just memorising the teacher's outputs and errors.

Common mistakes

  • Assuming the detector knows your classes (doorbell is not in COCO).
  • Treating presence as sound: the visible object is usually silent.
  • Aligning by frame index instead of timestamps on a shared clock.
  • Using raw co-occurrence counts instead of lift or PMI.
  • No hand-labelled check set, so confirmation bias goes unnoticed until the end.
  • Committing recordings of people to the repository.
