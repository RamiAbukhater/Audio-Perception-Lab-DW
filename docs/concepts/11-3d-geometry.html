The big idea

An ordinary camera tells you the direction of everything it sees but not the distance. An RGB-D camera (Intel RealSense, Azure Kinect, Orbbec, or an iPhone's LiDAR) adds a depth image: for each pixel, how far away the surface is. With the camera's intrinsics, each depth pixel becomes a 3-D point, and the whole image becomes a point cloud. Fit planes to the point cloud and you have walls and a floor; you have a geometric model of the room that an acoustic direction can be checked against.

The pinhole camera

The standard camera model projects a 3-D point \((X, Y, Z)\), in the camera's own frame, to pixel \((u, v)\):

\[ u = f_x \frac{X}{Z} + c_x, \qquad v = f_y \frac{Y}{Z} + c_y, \qquad K = \begin{pmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{pmatrix}. \]
  • \(f_x, f_y\): focal lengths in pixels. Larger means more zoomed in.
  • \(c_x, c_y\): the principal point, roughly the image centre.
  • \(K\) is the intrinsic matrix. It comes from the camera's SDK (RealSense reports it per stream) or from a checkerboard calibration with OpenCV.

The camera frame convention used by OpenCV, RealSense, and Open3D: \(x\) right, \(y\) down, \(z\) forward out of the lens. Many robotics and graphics tools use other conventions (\(z\) up, or \(y\) up). Write down which you use.

Depth to point cloud

Invert the projection, using the measured depth \(Z\) at each pixel:

\[ X = \frac{(u - c_x)\,Z}{f_x}, \qquad Y = \frac{(v - c_y)\,Z}{f_y}. \] 
import numpy as np

def depth_to_points(depth, fx, fy, cx, cy, depth_scale=1000.0):
    """depth: (H, W) uint16 depth image. Returns (N, 3) points in metres, camera frame."""
    h, w = depth.shape
    u, v = np.meshgrid(np.arange(w), np.arange(h))   # pixel column and row indices
    z = depth.astype(np.float32) / depth_scale       # RealSense: 1 unit = 1 mm by default
    x = (u - cx) * z / fx
    y = (v - cy) * z / fy
    pts = np.stack([x, y, z], axis=-1).reshape(-1, 3)
    return pts[pts[:, 2] > 0]                        # depth 0 means "no measurement"
  • Depth units: raw depth is an integer. RealSense uses millimetres by default (depth_scale = 0.001 m per unit, so divide by 1000); other sensors differ. Check the SDK.
  • Zero depth marks pixels with no valid reading (shiny, black, or too-distant surfaces, and the edges of objects). Drop them; never treat them as points at the camera.
  • Depth and colour are separate sensors with different intrinsics and positions. Use the SDK's alignment (RealSense rs.align) to map depth into the colour image before combining them, and use the intrinsics of whichever stream you aligned to.

Coordinate frames and extrinsics

Module 3 fuses data from at least three frames: the camera frame, the microphone array frame, and a room (world) frame. A rigid transform maps one frame to another, with a rotation \(R\) (3×3) and translation \(t\) (3-vector): \(p_{\text{cam}} = R\,p_{\text{array}} + t\). These are the extrinsics. Often they are written as one 4×4 homogeneous matrix \(T\).

  • Points transform with rotation and translation. Directions (such as a DOA unit vector) transform with rotation only: \(u_{\text{cam}} = R\,u_{\text{array}}\).
  • Getting \(R, t\): mount the array rigidly on the camera and measure the offset with a ruler; then refine by playing a sound from a few known positions (a phone the camera can also see) and solving for the rotation that best aligns the acoustic directions with the visual ones.
  • Room frame: choose the floor plane as \(z = 0\) (or \(y = 0\)) and align axes with the walls. Expressing everything in the room frame makes walls simple planes like \(x = 0\) and \(x = L_x\), which the mirror-source method in Concept 12 needs.
def to_frame(points, R, t):
    """Rigidly transform (N, 3) points: p' = R p + t."""
    return points @ R.T + t

u_cam = R_cam_from_array @ u_array            # a direction: rotate, never translate

Point clouds in Open3D

Open3D handles point clouds, meshes, RGB-D images, and visualisation. A typical pipeline:

import open3d as o3d

color = o3d.io.read_image("color.png")
depth = o3d.io.read_image("depth.png")                      # aligned to color, uint16 millimetres
rgbd = o3d.geometry.RGBDImage.create_from_color_and_depth(
    color, depth, depth_scale=1000.0, depth_trunc=6.0, convert_rgb_to_intensity=False)
intr = o3d.camera.PinholeCameraIntrinsic(width, height, fx, fy, cx, cy)
pcd = o3d.geometry.PointCloud.create_from_rgbd_image(rgbd, intr)

pcd = pcd.voxel_down_sample(voxel_size=0.02)                # one point per 2 cm cube
pcd, _ = pcd.remove_statistical_outlier(nb_neighbors=20, std_ratio=2.0)
pcd.estimate_normals(o3d.geometry.KDTreeSearchParamHybrid(radius=0.1, max_nn=30))
o3d.visualization.draw_geometries([pcd])
  • depth_trunc drops points beyond 6 m, where consumer depth is unreliable.
  • Voxel downsampling makes the cloud uniform and much smaller. A 640×480 depth image is 300k points; a 2 cm voxel grid of a room is a few tens of thousands.
  • Normals (the direction perpendicular to the local surface) tell walls (horizontal normals) from floor and ceiling (vertical normals).
  • A single view sees only part of the room. For a fuller map, capture several views and register them (Open3D's ICP, or its RGB-D integration with TSDF volumes), or use a static camera and accept that the map covers only the visible part, which is itself an interesting "out-of-sight" condition.

Finding walls with RANSAC

Rooms are mostly planes. RANSAC (random sample consensus) finds the dominant plane: repeatedly pick 3 random points, fit the plane through them, count how many other points lie within a small distance (the inliers), and keep the plane with the most inliers. Remove those inliers and repeat to get the next plane.

planes, rest = [], pcd
for _ in range(6):                                          # floor, ceiling, up to four walls
    if len(rest.points) < 500:
        break
    model, inliers = rest.segment_plane(distance_threshold=0.03, ransac_n=3, num_iterations=2000)
    if len(inliers) < 2000:                                 # too small to be a wall
        break
    planes.append(np.array(model))                          # [a, b, c, d] with ax + by + cz + d = 0
    rest = rest.select_by_index(inliers, invert=True)

Each plane is \(n \cdot p + d = 0\) with unit normal \(n = (a, b, c)\). Classify planes by their normal: nearly parallel to gravity means floor or ceiling, nearly perpendicular means a wall. Large furniture (a bookshelf, a partition) also shows up as planes, and those matter: they are the occluders in Module 3.

Doorways and openings appear as gaps in a wall plane: regions inside the wall's extent with no inlier points. Project the wall's inliers onto the plane and look for empty rectangles in a 2-D occupancy grid.

Ray casting

The key geometric query for Module 3 is: starting at the microphone array, travelling along the DOA direction, what do I hit first, and how far away is it? For a plane this has a closed form. Points on the ray are \(o + s\,u\) for \(s > 0\); substitute into the plane equation:

\[ s^* = -\frac{n \cdot o + d}{n \cdot u}. \] 
def ray_hits_plane(origin, direction, plane, max_dist):
    """Distance along the ray to the plane, or None if it misses within max_dist."""
    n, d0 = plane[:3], plane[3]
    denom = n @ direction
    if abs(denom) < 1e-6:                    # ray parallel to the plane
        return None
    s = -(n @ origin + d0) / denom
    return s if 0 < s < max_dist else None

Infinite planes are a simplification; a real wall has edges and a doorway has a hole. For finite geometry, build a triangle mesh (from the planes' extents, or by surface reconstruction of the point cloud) and use Open3D's o3d.t.geometry.RaycastingScene, which casts thousands of rays against a mesh at once and returns the hit distance and the triangle hit for each.

Simulated data

The spec allows "simulated depth datasets", and starting in simulation is wise: you get exact ground truth for source positions, walls, and occlusion.

  • SoundSpaces (Chen et al., 2020; SoundSpaces 2.0, 2022) renders realistic audio for 3-D scanned rooms (Replica and Matterport3D) together with RGB-D views. It is the closest existing tool to Module 3: real geometry, acoustics that include occlusion and reflections, and matching camera images.
  • pyroomacoustics: shoebox and polygonal rooms with the image-source method, multichannel microphone arrays, and DOA algorithms. Easy to start with, no visuals.
  • Real RGB-D datasets for testing the geometry stream alone: ScanNet, SUN RGB-D, Replica, and NYU Depth v2.

Check your understanding

Q1.\(f_x = 600\), \(c_x = 320\). A pixel at \(u = 470\) has depth 2.0 m. What is its \(X\)?

\(X = (470 - 320) \times 2.0 / 600 = 0.5\) m, half a metre to the right of the optical axis.

Q2.Why does a DOA direction transform with \(R\) only, while a point transforms with \(R\) and \(t\)?

A direction is a difference between two points; translating both by \(t\) cancels out. Moving the array 10 cm sideways does not change which way "north-east" is.

Q3.RANSAC returns a plane with normal (0, −0.99, 0.1) in the camera frame. Floor, ceiling, or wall?

In the camera frame \(y\) points down, so a normal along \(\pm y\) means a horizontal surface: floor or ceiling. Which one depends on which side of the plane the camera is on (compare the sign of \(d\), or check the plane's height relative to the camera). The small \(z\) component means the camera is tilted slightly.

Q4.A ray from the array along the DOA hits a wall plane at 1.2 m, but the visual detector shows the sound's likely source 3 m away in that direction. What does that suggest?

The visual candidate is behind the wall, so it cannot be the direct-path source along that ray. Either the DOA is a reflection, or the true source is occluded or elsewhere. This is exactly the reasoning Concept 12 formalises.

Common mistakes

  • Wrong depth units (millimetres as metres), giving a room a kilometre wide.
  • Unaligned depth and colour, so detections in the colour image get depths from the wrong pixels.
  • Mixing frame conventions (\(y\) down versus \(z\) up) between libraries.
  • Translating direction vectors.
  • Treating zero depth as real, creating a cloud of points at the camera.
  • Trusting one view as a complete room map; mark which parts of the room are unobserved.
