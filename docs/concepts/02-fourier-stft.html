The Fourier transform and the STFT

A waveform tells you how loud the sound is from moment to moment, but almost nothing about what it is. A dog bark and a car horn at the same volume look alike as waveforms and completely different as spectra. This page is about how we move from time to frequency, and why we always do it in short windows.

The big idea

Any signal can be written as a sum of sine waves of different frequencies, each with its own amplitude and starting phase. The Fourier transform finds those ingredients. Think of it as a recipe card: "a lot of 440 Hz, a little 880 Hz, a pinch of 1320 Hz" describes a violin's A string far better than 16,000 sample values do.

Real sounds change over time, though. A siren sweeps, a door slams once, speech changes every few tens of milliseconds. One Fourier transform of a whole 4-second clip would mix all of that into a single recipe and lose the timing. So we slice the signal into short, overlapping frames and take the Fourier transform of each. That is the short-time Fourier transform (STFT), and its magnitude, drawn as an image, is the spectrogram: time on the x-axis, frequency on the y-axis, energy as brightness.

The DFT and the FFT

For a block of \(N\) samples, the discrete Fourier transform computes \(N\) complex numbers:

\[ X[k] = \sum_{n=0}^{N-1} x[n]\, e^{-2\pi i\, k n / N}, \qquad k = 0, 1, \dots, N-1. \]

Read it as: "for each frequency \(k\), correlate the signal with a sine and cosine at that frequency." A large \(|X[k]|\) means the signal contains a lot of that frequency. Bin \(k\) corresponds to

\[ f_k = \frac{k\, f_s}{N}\ \text{Hz}, \qquad \Delta f = \frac{f_s}{N}. \]

For real-valued audio the second half of the bins mirrors the first, so libraries keep only \(N/2 + 1\) bins, from 0 Hz up to Nyquist. With \(N = 1024\) at 16 kHz you get 513 bins spaced 15.6 Hz apart.

The fast Fourier transform (FFT) is just a clever algorithm for computing the DFT in \(O(N\log N)\) instead of \(O(N^2)\) operations. It works fastest when \(N\) is a power of two, which is why window sizes are almost always 256, 512, 1024, or 2048.

Windows and spectral leakage

Cutting a frame out of a signal with sharp edges is like multiplying it by a rectangle. Those sharp edges are themselves "high-frequency" events, and they smear energy from each true frequency into its neighbours. That smear is called spectral leakage.

The fix is to taper each frame smoothly to zero at both ends before the FFT by multiplying it with a window function. The Hann window is the default almost everywhere:

\[ w[n] = \tfrac12\left(1 - \cos\frac{2\pi n}{N}\right). \]

Tapering the edges throws away information there, so frames overlap: each new frame starts one hop later than the previous one, usually a quarter or half of the window length. With a Hann window and 50% or 75% overlap, every sample is counted evenly overall.

The short-time Fourier transform

Putting it together, the STFT at frame \(m\) and frequency bin \(k\) is

\[ X[m, k] = \sum_{n=0}^{N-1} x[n + mH]\, w[n]\, e^{-2\pi i\, kn/N}, \]

where \(N\) is the window length (n_fft) and \(H\) is the hop (hop_length). Frame \(m\) starts at sample \(mH\). The result is a 2-D complex array of shape (n_fft/2 + 1, n_frames).

With center=True (the default in PyTorch and librosa) the signal is padded by \(N/2\) on each side so that frame \(m\) is centred exactly on sample \(mH\). Then the number of frames is \(1 + \lfloor L / H \rfloor\) for a signal of \(L\) samples.

The time-frequency trade-off

This is the single most important intuition on the page. A window of \(N\) samples lasts \(N / f_s\) seconds and has bins \(f_s / N\) Hz apart. Multiply them: the product is always 1. You cannot make both small at once.

  • Long windows (2048 at 16 kHz = 128 ms): fine frequency detail (7.8 Hz bins), but a short click is smeared across the whole 128 ms.
  • Short windows (256 at 16 kHz = 16 ms): sharp timing, but bins 62.5 Hz wide, so close pitches merge.

For environmental sound classification a window of about 25 to 64 ms with a 10 ms hop is a sensible default. Speech systems usually use 25 ms windows with a 10 ms hop.

Magnitude, power, and phase

Each STFT value is a complex number \(X = |X|e^{i\phi}\). Its magnitude \(|X|\) says how much of that frequency is present; its phase \(\phi\) says where in its cycle the wave is. The power spectrogram is \(|X|^2\).

  • Classification models (Module 1) throw the phase away and use magnitude or power, usually on a log scale.
  • Localization (Module 2) needs exactly the opposite: the phase difference between two microphones encodes the time delay. GCC-PHAT keeps only phase and discards magnitude. Same transform, opposite halves.

The code

import torch

n_fft, hop = 1024, 256                      # 64 ms window, 16 ms hop at 16 kHz
y = wav[0]                                  # mono waveform: (samples,)

S = torch.stft(
    y,
    n_fft=n_fft,
    hop_length=hop,
    window=torch.hann_window(n_fft),        # always pass a window explicitly
    center=True,                            # pad so frame m is centred on sample m*hop
    return_complex=True,
)                                           # S: (n_fft//2 + 1, n_frames), complex64
power = S.abs() ** 2                        # power spectrogram
power_db = 10 * torch.log10(power + 1e-10)  # in dB, for plotting

freqs = torch.fft.rfftfreq(n_fft, d=1 / 16_000)   # Hz for each row
times = torch.arange(S.shape[1]) * hop / 16_000   # seconds for each column
  • For a 1-second clip at 16 kHz: (16000,) → (513, 63), since \(1 + \lfloor 16000/256 \rfloor = 63\).
  • Without window=, torch.stft uses a rectangular window and warns you. Leakage will make the spectrogram look blurry.
  • rfftfreq and times are the axis labels. Plot with plt.pcolormesh(times, freqs, power_db) so the axes are in real units, not bin indices.

Check your understanding

Q1.At 16 kHz with n_fft = 512, how long is each window and how far apart are the bins?

512 / 16000 = 32 ms per window. Bins are 16000 / 512 = 31.25 Hz apart, and there are 257 of them.

Q2.You want to tell apart two engine hums at 100 Hz and 110 Hz. What is the smallest power-of-two n_fft at 16 kHz that gives bins narrower than their gap?

You need \(16000 / N < 10\), so \(N > 1600\): n_fft = 2048 (7.8 Hz bins, a 128 ms window). In practice you want a few bins between them because the Hann window widens each peak, so 4096 is safer.

Q3.Why do we use overlapping frames?

The window tapers each frame to zero at its edges, so samples near the edges barely count. Overlap makes sure every part of the signal is near the centre of some frame, and it gives a smoother time axis.

Q4.Why can a classifier ignore phase but a localizer cannot?

What a sound is depends mostly on how its energy is spread over frequency and time, which magnitude captures. Where it comes from shows up as a tiny time shift between microphones, and a time shift changes only the phase of each frequency.

Common mistakes

  • Not passing a window to torch.stft, which defaults to a rectangle and leaks energy everywhere.
  • Plotting linear power: a few loud bins dominate and everything else looks black. Plot in dB.
  • Labelling axes with bin indices instead of Hz and seconds, then misreading which sound is which.
  • Changing n_fft or hop between training and deployment. The model sees a different image and accuracy collapses. Treat the front-end parameters as part of the model.
  • Forgetting center=True padding when converting frame indices back to times, which shifts every event by half a window.
