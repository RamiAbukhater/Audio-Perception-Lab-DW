Where to run things

  • Your laptop, for everything except long training runs: data processing, DSP, the room simulations, and debugging. Any recent Mac, Windows, or Linux machine is fine.
  • Google Colab or Kaggle, for training on a free GPU. Kaggle gives about 30 GPU hours a week; Colab's free tier varies.
  • Hardware (a microphone array and an RGB-D camera) is shared and only needed in the real-room phase of the project. Ask the lab leads.

Local install

Install Python 3.11

We standardise on Python 3.11 because every library the lab uses (including Open3D) ships wheels for it. Use one of:

  • uv (fast, recommended): it can install Python for you.
  • Miniconda, if you already use conda.

Clone the repository

git clone https://github.com/<org>/dataworks-audio-perception-lab.git
cd dataworks-audio-perception-lab

Replace <org> with the GitHub organisation or user that hosts the lab repository.

Create an environment and install the requirements

With uv:

uv venv --python 3.11
source .venv/bin/activate          # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt

Or with conda:

conda create -n audiolab python=3.11 -y
conda activate audiolab
pip install -r requirements.txt

requirements.txt is grouped by part of the project. If a heavy package fails to install (Open3D on an unusual platform, for example) and you are not working on that part yet, comment it out and carry on.

Run the smoke test

python scripts/smoke_test.py

It mixes a chirp with noise at exactly 10 dB SNR, writes and reads a WAV file, computes the lab's log-mel front end, runs a tiny CNN, checks that GCC-PHAT finds a known 5-sample delay, and saves smoke_test.png. Expected output (versions will differ):

Python 3.11.9
  ok       numpy 1.26.4, torch 2.5.1, torchaudio 2.5.1
Optional packages:
  ok       soundfile 0.12.1
  ...
[1] mixed at 10.00 dB SNR (target 10.00)
[2] wrote and read smoke_test.wav: 32000 samples at 16000 Hz
[3] log-mel shape (1, 64, 101)
[4] CNN forward pass ok, 1194 parameters
[5] GCC-PHAT found a delay of 5 samples (expected 5)
[6] saved smoke_test.png

All checks passed.

Open smoke_test.png. You should see a bright line rising from bottom-left to top-right (the chirp) over a speckled background (the noise). If you can explain why the line curves upward on the mel axis faster at first and then slows, you have already understood Concept 3.

GPU notebooks

  1. Open a new notebook on Colab (Runtime → Change runtime type → GPU) or Kaggle (Settings → Accelerator → GPU; Kaggle requires phone verification for GPUs and internet access).
  2. Clone and install in the first cell. PyTorch and torchaudio are preinstalled, so install only what is missing: 
    !git clone https://github.com/<org>/dataworks-audio-perception-lab.git
%cd dataworks-audio-perception-lab
!pip install -q pyroomacoustics soundfile
  3. Check the GPU: import torch; torch.cuda.is_available() should be True.
  4. Notebook storage is wiped when the session ends. Save checkpoints and results to Google Drive (Colab) or as a Kaggle dataset/output.

Getting the data

  • UrbanSound8K (the warm-up dataset used on the core concept pages): about 6 GB. Download from the dataset page or the copy on Zenodo, unpack outside the repository (for example ~/datasets/UrbanSound8K), and point scripts at it with an environment variable such as US8K_ROOT. On Kaggle, add a public copy of the dataset to your notebook instead of downloading.
  • Noise and RIRs: MUSAN, DEMAND, and the OpenSLR RIR database (links on Concept 4 and Resources).
  • Never commit data, recordings, or model checkpoints. The .gitignore already excludes common audio, video, and weight file types. UrbanSound8K is CC BY-NC, and the project's recordings contain people.

Working in the repository

  • Work on a branch named after you and your task: git switch -c alex/m2-gcc-phat.
  • Put code in the project folders listed in the repository README, and notebooks in notebooks/ with your name in the filename.
  • Open a pull request early, even unfinished, so others can see what you are doing and reuse it.
  • Shared pieces (the log-mel front end, the SNR mixer, GCC-PHAT) should live in one place and be imported, not copied between notebooks.

Troubleshooting

torchaudio.load complains about a missing backend or torchcodec
Recent torchaudio versions moved audio decoding to the separate torchcodec package. Either pip install torchcodec (it needs FFmpeg installed), or load with soundfile.read(path, dtype="float32") and convert with torch.from_numpy(x.T), remembering soundfile's (samples, channels) layout.
Open3D fails to install
Check that you are on Python 3.11 (Open3D lags new Python releases), and on Apple Silicon that you are using a native arm64 Python. Only the room map needs it.
NumPy 2 errors such as "A module that was compiled using NumPy 1.x cannot be run in NumPy 2"
An older package was built against NumPy 1. Upgrade that package, or pin pip install "numpy<2" in this environment.
No sound from IPython.display.Audio
Pass the sample rate (rate=16000) and a 1-D float array. Some notebook hosts block autoplay; click play.
