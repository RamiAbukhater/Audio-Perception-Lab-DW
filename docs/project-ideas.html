1 Lightweight edge audio classification and robustness testing

Edge deploymentUrbanSound8KPyTorch · ONNX RuntimeESP32 / Pico targets

Objective. Build, compress, and benchmark compact audio neural networks (for example MobileNet-based or custom tiny CNNs) under simulated hardware constraints and extreme environmental noise.

Technical outline.
  • Data pipeline: scripts to process datasets (for example UrbanSound8K) with synthetic data augmentations including pink and white noise injection, room impulse response (RIR) reverberation, and dynamic gain drops.
  • Model architecture: compact audio feature extractors operating on log-mel spectrogram frames.
  • Quantization and optimization: 8-bit integer post-training quantization (PTQ) and weight pruning, using tools like PyTorch or ONNX Runtime, targeting microcontrollers (ESP32 and Raspberry Pi Pico specs).
  • Evaluation suite: benchmarking scripts tracking inference latency, memory footprint (RAM and flash), and accuracy degradation curves under varying signal-to-noise ratios (SNR).

Suggested path.
  1. Pipeline and baseline. Load UrbanSound8K with its official folds, resample to 16 kHz mono, fixed 4 s clips, the shared log-mel front end. Train a float32 TinyAudioNet and an MFCC + SVM baseline.
  2. Stressed test sets. Generate and save fixed test sets at −10, −5, 0, 5, 10, 20 dB with held-out white, pink, and real noise; reverberant versions at several RT60s; gain-drop versions. Draw the first degradation curves.
  3. Robust training. Retrain with on-the-fly augmentation. Does it flatten the curve? At what cost to clean accuracy?
  4. Compression. PTQ to int8 (PyTorch and ONNX Runtime), then structured and unstructured pruning, then QAT if PTQ loses too much. Evaluate every variant on every stressed test set.
  5. Benchmark. Single-thread, batch-1 latency (p50, p95) including the front end; flash and peak RAM; check each variant against ESP32 and Pico budgets. Deploy the best one on real hardware if available.
Key result. One figure: accuracy versus SNR, one line per model variant (float, int8, pruned, each with and without noise training), plus a table of size, RAM, and latency. The research question: does compression cost more accuracy in noise than in clean conditions?
Extensions.
  • Knowledge distillation from a large pretrained teacher (PANNs, AST) into the tiny student; how much of the noise-robustness gap closes?
  • Mixed precision: keep the first and last layers in higher precision and measure what that buys.
  • Streaming inference with a rolling buffer and the always-on power budget it implies.
  • Per-class robustness: which classes collapse first in noise, and why?

Needs: a laptop and free Colab/Kaggle GPU time. Optional: an ESP32-S3 or Raspberry Pi Pico 2 board and a Raspberry Pi for real latency numbers.

2 Self-supervised audio learning via vision grounding

Self-supervisedCross-modalYOLOv8 (frozen)Indoor recordings

Objective. Bootstrap an indoor audio classifier iteratively, using visual co-occurrence cues (for example YOLO object detection), without relying on manually labelled sound datasets from scratch.

Technical outline.
  • Multimodal synchronization engine: captures time-aligned windows of ambient audio and RGB frames from a static indoor camera setup.
  • Visual object detection wrapper: integrates a frozen object detector (for example YOLOv8) to extract bounding boxes and semantic class labels (microwave, keyboard, doorbell) from the visual stream.
  • Cross-modal gating and pseudo-labeling:
    • computes audio embedding clusters via unsupervised representation learning;
    • implements a confidence-scoring policy: if audio clusters align temporally with high-confidence visual object tags, assign a pseudo-label.
  • Iterative fine-tuning loop: periodically updates the student audio encoder weights using auto-curated pseudo-labels, to measure classification convergence over generation cycles.

Suggested path.
  1. Capture rig and consent. One static camera and one microphone on the same machine, both stamped with one monotonic clock. Clap test to measure offset. Get consent from everyone who uses the space; agree on what is stored and for how long.
  2. Class list and check set. Pick 6–10 indoor sound classes. Confirm the detector's vocabulary covers them (COCO has microwave and keyboard but no doorbell; plan an open-vocabulary detector or another visual cue). Hand-label 200+ windows from held-out days as the test set.
  3. Generation 0. Embed windows with a pretrained encoder, drop silence, over-cluster, compute cluster–tag lift, apply the gate, inspect and listen to every cluster that received a label.
  4. Iterate. Train the student with strong augmentation, relabel, re-embed, re-cluster. Track test macro-F1, pseudo-label precision and coverage, and cluster quality per generation.
  5. Out-of-view test. Does the final audio model recognise events when the object is off camera? Compare with a supervised model trained on the hand labels alone.
Key result. Convergence curves over generations (macro-F1, pseudo-label precision, number of labelled windows), compared against a small fully supervised baseline. The research question: how close can vision-grounded pseudo-labels get to human labels, and where does confirmation bias set in?
Extensions.
  • Learned gating: replace fixed thresholds with a small model that predicts whether a pseudo-label is correct.
  • Activity cues instead of object presence (hand–object proximity, door state changes).
  • Contrastive audio pretraining on the unlabelled recordings before generation 0.
  • Transfer: train in one room, test in another.

Needs: a webcam and a USB microphone (or a laptop's built-in ones), a GPU for training, and a shared indoor space where everyone has agreed to be recorded.

3 Audio-visual sound source localization (AV-SSL) with spatial physics

Spatial audioGCC-PHATRGB-D · Open3DPhysics reasoning

Objective. Build an advanced localization pipeline that integrates spatial audio direction with 3-D room geometry, to resolve occlusions, off-screen sound sources, and echoes.

Technical outline.
  • Stream A, acoustic direction of arrival: implements generalized cross-correlation with phase transform (GCC-PHAT) on microphone array feeds to calculate incoming sound azimuth and elevation angles.
  • Stream B, visual room mapping: interfaces with an RGB-D camera (or simulated depth datasets) to extract 3-D point clouds, wall locations, and layout boundaries using open-source tools (for example Open3D).
  • Stream C, physics and occlusion reasoning layer:
    • Line-of-sight check: cross-references the acoustic DOA vector against the 3-D room layout map.
    • Occlusion and out-of-sight handling: filters out false-positive visual heatmaps when a sound vector points toward a blocked wall or open doorway, classifying the source as occluded.
    • Multi-path reflection mapping: uses basic acoustic mirror-source concepts to track early wall reflections, rather than letting the model hallucinate false visual origins.
  • Evaluation benchmarks: measures angular localization error (degrees) and classification accuracy across visible versus occluded source scenarios.

Suggested path.
  1. Simulation first. Build test rooms in pyroomacoustics (shoebox, then with partitions) with a simulated array. Implement GCC-PHAT and SRP-PHAT; reproduce the anechoic-versus-reverberant gap; tabulate angular error against RT60.
  2. Geometry stream. From RGB-D frames (a simulated dataset or a RealSense), produce a point cloud, RANSAC planes for floor and walls, doorway gaps, and a ray-casting query.
  3. Calibration. Put array, camera, and room in one frame. Validate with a phone playing noise from known positions.
  4. Physics layer. Line-of-sight check, occlusion and off-screen classification, first-order reflection mapping. Ablate each.
  5. Benchmark. Visible, occluded, and off-screen scenarios in simulation, then in a real room. Report wrapped angular error (median, within 10° and 20°), scenario classification accuracy, and hallucinated-source rate against DOA-only and naive-fusion baselines.
Key result. A table of angular error and scenario accuracy split by visible, occluded, and off-screen, with and without each physics step. The research question: how much does explicit room geometry reduce localization errors and false visual matches caused by occlusion and reflections?
Extensions.
  • SoundSpaces scenes for realistic geometry with rendered audio and RGB-D.
  • Probabilistic fusion: a likelihood for each explanation instead of thresholds; tracking over time.
  • Second-order reflections and diffraction around doorway edges.
  • A learned AV-SSL heatmap model as Stream D, with the physics layer used to veto its impossible answers.

Needs: Python and pyroomacoustics for the simulation phase. For the real-room phase: a synchronised multichannel array (for example a ReSpeaker 4- or 6-mic array) and an RGB-D camera (for example an Intel RealSense).

How to pick and propose

  1. Finish setup and the six core concept pages, so you can judge each module from the inside.
  2. Read the module pages for the one or two modules you are drawn to.
  3. Write a half-page proposal: which module, which question within it (one of the extensions, or your own), the single figure or table you expect to produce, the baseline you will beat, and the data and hardware you need.
  4. Bring it to the lab leads. Teams can split a module by stream or stage (for example one person on Module 3's Stream A and another on Stream B), as long as the interfaces between pieces are agreed in writing first.
